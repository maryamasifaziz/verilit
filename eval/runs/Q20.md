# How are large language models used to find vulnerabilities in source code?

## Literature review

Large language models (LLMs) are utilized for automated vulnerability detection in source code by employing prompt design, parameter fine-tuning, and program-context information to determine whether code contains vulnerabilities and to highlight suspicious locations [1]. To improve recall, F1 score, and explanatory utility, methods such as context enhancement, program-analysis guidance, retrieval augmentation, specification-guided reasoning, and collaborative decision-making are applied [2]. 

To assess these models, benchmark datasets and evaluation metrics are necessary. Evaluations leverage frameworks built with benchmarks like MegaVul [3], as well as the Software Assurance Reference Dataset (SARD) and the National Vulnerability Database (NVD), utilizing metrics including accuracy, precision, recall, and F1-score [4]. 

Mixed results have been reported regarding the effectiveness of LLMs compared to traditional tools. While one study highlights a significant performance gap between LLMs and popular static analysis tools due to high false positive rates in LLMs [5], another study demonstrates that the proposed LLM-VDM model achieved 91.2% accuracy, a 90.0% F1-score, and a 0.94 AUC, outperforming baseline and deep learning competitors such as SonarQube, Devign, CodeBERT, and CodeT5 [6]. 

Despite these advancements, applying LLMs to software vulnerability discovery presents primary limitations, challenges, and security risks. Current approaches rely heavily on online API-based services, which requires users to disclose their source code during development [7]. Additionally, ChatGPT exhibits a constrained ability to process long code contexts when performing security-related tasks [8].

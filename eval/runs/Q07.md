# How is federated learning used to train models while preserving data privacy?

## Literature review

Federated learning utilizes several core cryptographic and anonymization techniques to safeguard data privacy against adversarial threats. These mechanisms include differential privacy, homomorphic encryption, multi-party computation, and trusted execution environments [1, 2]. 

To maintain model accuracy during decentralized training, approaches such as the simple federated averaging technique have been shown to build more accurate models than training exclusively on local data [3]. Additionally, the FedQuad method addresses data heterogeneity and maintains model performance by optimizing smaller intra-class variance and larger inter-class variance across clients [4]. 

Evaluation of privacy-preserving federated learning relies on diverse benchmark datasets and simulation frameworks. For example, the MC-DQE FL framework was evaluated using the CIFAR-10 and FMNIST datasets [5], while a federated Random Forest framework utilized PySyft for secure computation and was assessed on two real-world healthcare benchmarks [6]. 

Despite these advancements, privacy mechanisms and decentralized training in federated learning present notable limitations, security vulnerabilities, and trade-offs. The paradigm faces challenges such as increased computational complexity, high communication overhead between peers, non-iid node data, and client heterogeneity driven by dataset size and bias [7, 8].

# What are prompt injection attacks on LLM-based applications and how can they be mitigated?

## Literature review

Prompt injection attacks represent a significant security concern in large language models (LLMs). Research into their core mechanisms includes early categorizations designed to serve as vulnerability checklists during LLM interface development [1], as well as specific strategies such as the goal-guided generative prompt injection strategy (G2PIA), which maximizes the Kullback-Leibler (KL) divergence between the conditional probabilities of clean and adversarial text, equivalently maximizing the Mahalanobis distance between their embedded representations [2].

To secure LLM applications, various defense and mitigation techniques have been proposed [3, 4]. Among early prompt leak detection solutions, Vigil is optimal for applications requiring a minimal false positive rate, while Rebuff is most optimal for average needs [3]. Furthermore, universal tool-based defenses—specifically Attacker Tool Filtering and Normal Tool Recalling—alongside prompt-based defenses like Chain-of-Thought prompting, self-reflection, and task paraphrasing, have been shown to significantly reduce Attack Success Rates [4].

Testing these vulnerabilities relies on specialized datasets, benchmarks, and evaluation frameworks [5, 6]. For instance, Gate AI evaluates prompt-injection and jailbreak detectors utilizing 16 public benchmarks comprising 12,111 samples with 5-fold cross-validation [5]. Additionally, GenTel-Safe introduces GenTel-Bench, which is an evaluation benchmark containing 84,812 prompt injection attacks categorized into 3 major categories spanning 28 security scenarios [6].
